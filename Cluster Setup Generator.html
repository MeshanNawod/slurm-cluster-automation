Slurm 26.05 Configuration Tool + Cluster Setup Generator

One page for the whole setup. Tab 1 builds the setup scripts with your values built in. Tab 2 builds slurm.conf (the Slurm 26.05 configuration tool, with node groups for machines that are not identical). The zip contains the scripts and slurm.conf together.

Download

.sh files cannot be downloaded alone from a page, so they come in one zip. Then run unzip cluster-scripts.zip. If the download is blocked, use the copy buttons.

IP plan (head IP is skipped)

IPs follow node0 + number. If a node has a different IP, type it in its row; the scripts then use your IP for that node. A changed row is marked "custom".

What each script still asks

node-setup.sh          (each worker): node name (e.g. node3); Enter accepts the calculated IP
head-setup.sh          (head)        : password; "Set up only ONE node?" (Enter = all nodes)
node-setup-in-head.sh  (head)        : same as head-setup.sh, also turns off automatic upgrades

head-setup.sh has three modes (node-setup-in-head.sh has the same):
  bash head-setup.sh                      set up SSH, time, hosts, packages, munge, NFS
  bash head-setup.sh slurm                install slurm.conf (from this zip), start slurmd and slurmctld
  bash head-setup.sh reboot [--no-head]   reboot the nodes (--no-head leaves the head alone)

Order: node-setup.sh on every node -> head-setup.sh -> head-setup.sh slurm
(keep slurm.conf in the same folder as head-setup.sh)

node-setup.sh also turns off automatic updates and sleep on each worker, and warns if a reboot is pending. To add or repair ONE node, answer its index at "Set up only ONE node?" and type its IP when asked. Use node-setup-in-head.sh instead of head-setup.sh for nodes set up with an older node-setup.sh.

Which Slurm do you run? This tool follows the Slurm 26.05 configuration tool. Ubuntu's apt package is older and may not work with cgroup settings (check with slurmctld -V).

Cluster and queue

Compute nodes (node groups)

One row per hardware type. Machines with different CPUs or memory need their own row, otherwise Slurm marks the weaker ones inval. Give CPUs, or Sockets, CoresPerSocket and ThreadsPerCore. Set RealMemory a little below what slurmd -C reports. Weight: nodes with a lower weight are used first. Feature: a tag users can request with --constraint.

Fill the groups automatically from slurmd -C

Run this on the head, paste the output below, and click the button. Nodes with the same hardware are grouped, and memory is set to 95% of the smallest value in each group.
